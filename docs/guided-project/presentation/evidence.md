# Evidence and limits for the 12-slide Data Team deck

The current saved deliverable is [`presentation_bpa.pptx`](../slides/presentation_bpa.pptx), with eight core slides and four optional appendices. The presentation uses **three evidence levels**: static source definitions in this repository; one bounded **adapted, synthetic local** order run on 16 November 2026; and proposals requiring agreement or validation. The detailed runtime report was produced outside this repository and is **not** part of this PR: local counts below describe that isolated snapshot, not independently reproducible public trace data or the current physical lab. No individual physical-bike event sequence was verified.

| Slides | Basis | Boundary |
| --- | --- | --- |
| 1–2 — goal and path | `sql/initdb.sql:24–68` defines customer-order, production-order and bike records. `bpa_lab_manufacturing_process/src/main/java/de/thkoeln/inf/bpalab/demofactory/bpalabmanufacturing/mqtt/publisher/FtfactoryPubOrder.java:47–65` constructs an outgoing factory reference. `bpalab_mqtt_2_mongodb/src/main/kotlin/de/thkoeln/inf/bpalab/bpalab_mqtt_2_mongodb/domain/MqttEvent.kt:49–64` models stored order events. | SQL → MQTT → MongoDB → Trino is a useful conceptual path, **not** one fully observed end-to-end order. The Trino event read in the isolated run concerned a separate probe. |
| 3–4 — local observation | One synthetic customer order used stock plus production; the production path published an MQTT order. In that local snapshot, **zero** incoming order events matched its reference; **one** unrelated RED probe was stored. Station and BME680 events came from a periodic stream. | Neither a factory response, completed manufacturing, customer shipment nor a wrong live match was proved. Counts are not coverage estimates. The underlying local-run report is not included here; these observations must not be presented as physical-lab measurements. |
| 5 — time | `MqttEvent.kt:49–64` makes incoming `ts` transient and creates a receipt `timestamp`; `FtfactoryPubOrder.java:47–65` and `bpa_lab_manufacturing_process/src/main/java/de/thkoeln/inf/bpalab/demofactory/bpalabmanufacturing/time/UTCTime.java:13–22` produce a next-day outbound `ts`. `sql/initdb.sql:24–68` has a shipped flag, not a customer-shipment instant. | Source time, receipt time, factory `SHIPPED` and customer shipment are distinct. No clock defect or customer-shipment duration was established. |
| 6 — four packages | Proposed outputs: **1** factory-event contract, **2** explicit order/bike links, **3** process/time measures, **4** stable Trino business outputs. The existing `docker-dataarch.yml` and `trino-config/` describe the intended query stack; `../diagrams/sources.md` explains diagram sources. | Packages, persisted views, Dashboard Team adoption, access rights and stable mappings are **not** approved or proven. Data Team mapping raw sources behind an agreed Trino interface does not remove upstream identity, timing, privacy or availability requirements. |
| 7 — package 2 A/B | `FtfactorySubOrder.java:68–102` checks incoming bike `type` (colour in the local example), not the incoming exact factory reference. The publisher defines an outgoing reference. `bpalab_mqtt_2_mongodb/README.md:30–118` gives example order/station payloads; the station fields do not identify a bike instance. `bpa_lab_fake_factory/src/main/kotlin/de/thkoeln/bpalab/fakefactory/domain/TopicPayloadPreset.kt` is a simulator preset. | **A** proposes a unique reference in each relevant event and actual correlation by it; whether real replies echo it is unverified. **B*** proposes a variant-specific station-sequence template with a distinct tracked state for each bike. It assumes reliable station IDs/route, known entry/order binding and a unique candidate per step (e.g. proven FIFO or exclusivity). Inferred progress is **not** measured individual movement or guaranteed identity. Missing, duplicate or ambiguous messages must not be silently matched. |
| 8 — team questions | `grafana_dashboards/EreignisprotokollProcessMiningMYSQL.json:49–68` contains a query with `customer_name` and a filter excluding unfinished nodes. | An exported query is not an active-dashboard audit or a demonstrated privacy breach. Team input and professor prioritization are requests, not commitments. |
