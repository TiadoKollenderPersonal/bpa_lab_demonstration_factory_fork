| Visible entity/edge | Versioned evidence and interpretation |

| `BIKE_MODEL`, `BIKE_COMPONENT`, component→model | `sql/initdb.sql:5-22`: `title` PK on each; `bike_component.bike_model_id` non-null FK to `bike_model.title`. Parent exactly one per child, zero or many children per parent. |

| `CUSTOMER_ORDER`, `CUSTOMER_ORDER_ITEM`→order/model | `sql/initdb.sql:35-55`: text order PK; auto-increment item PK; item `order_id` nullable FK to order PK (zero or one order for each item), required `bike_model_id` FK. | `PRODUCTION_ORDER`→`BIKE_MODEL` | `sql/initdb.sql:58-68`: separate text production PK; required `bike_model_id` FK. Nullable `customer_order_number` is **not** a declared FK, so there is no drawn SQL order↔production relationship. |
| `PURCHASE_ORDER`→`BIKE_COMPONENT` | `sql/initdb.sql:70-81`: auto-increment PK; required component FK. Nullable `production_order_number` has **no** FK. |
| `VENDOR_BIKE_COMPONENT`→`VENDOR` and `BIKE_COMPONENT` | `sql/initdb.sql:83-99`: composite PK (`vendor_name`, `bikecomponent_title`), with two required FKs. A vendor/component can each have zero or many link rows; a link row has exactly one of each parent. |

Displayed attributes use DDL types and nullability; unshown columns (including customer personal data, vendor contact and purchase vendor name) still exist in the DDL. Auto-increment PKs and composite PK uniqueness are shown; there is no additional declared UNIQUE constraint. All eight drawn ERD edges correspond to actual declared foreign keys; nullable textual references `bike_instance.customer_order_number`, `production_order.customer_order_number`, `purchase_order.production_order_number` remain **attributes, not enforced relationships**. Even the observed same customer/production number `00000001` arose from distinct fresh counters, not an enforced identity. App-level correlation (`CustomerOrderWorker.java:84-100`; `ProductionControlWorker.java:117-137`) also creates no DDL FK. This ERD describes the **versioned initialization schema**, not verified deployed-lab constraints, migrations, or current rows. Initial SQL mount: `docker-compose-override.yml:18-43`. `R: Eingabe, Erwartung, tatsächliche Prozesskette` records one local order, one production row, one stock reservation; it does not certify every SQL edge from a live constraint introspection.
